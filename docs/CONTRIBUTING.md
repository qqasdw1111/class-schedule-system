
# Правила внесення змін до проєкту

## 1. Робочі гілки

- `main` — основна стабільна гілка.
- `feature/назва` — для нової функціональності.
- `bugfix/назва` — для виправлення помилок.
- `docs/назва` — для змін документації.

## 2. Повідомлення commit

Повідомлення commit мають коротко описувати зміни.

Приклади:
- `feat: додано пошук занять`
- `docs: оновлено документацію`
- `fix: виправлено перевірку даних`
- `chore: налаштовано репозиторій`

## 3. Pull Request

Зміни пропонуються через Pull Request із робочої гілки до `main`.

## 4. Перевірка змін

Перед злиттям необхідно перевірити опис змін, відповідність задачі та відсутність очевидних помилок.

## 5. Злиття

Після перевірки Pull Request можна об'єднати з `main`.
