# Інтерфейси компонентів Class Schedule System

## 1. Web Interface

**Призначення:** забезпечує взаємодію користувачів із системою.

Основні операції:
- Перегляд розкладу навчальної групи.
- Перегляд розкладу викладача.
- Перегляд інформації про заняття.
- Надсилання запитів на створення та редагування розкладу.

Вхідні дані:
- Ідентифікатор користувача.
- Ідентифікатор групи або викладача.
- Дані заняття.

Вихідні дані:
- Відображений розклад.
- Інформація про заняття.
- Повідомлення про результат операції.

## 2. Schedule Controller

**Призначення:** обробляє запити, пов'язані з керуванням розкладом.

Основні операції:
- createSchedule() — створення розкладу.
- editSchedule() — редагування розкладу.
- deleteSchedule() — видалення розкладу.
- getSchedule() — отримання розкладу.

Вхідні дані:
- Дані заняття.
- Ідентифікатор розкладу.
- Запити від Web Interface.

Вихідні дані:
- Результат виконання операції.
- Повідомлення про помилки.
- Дані розкладу.

## 3. Schedule Service

**Призначення:** реалізує бізнес-логіку керування розкладом.

Основні операції:
- validateSchedule() — перевірка коректності розкладу.
- checkConflicts() — перевірка конфліктів.
- saveSchedule() — збереження розкладу.
- updateSchedule() — оновлення розкладу.

Вхідні дані:
- Дані заняття.
- Інформація про викладача.
- Інформація про аудиторію.
- Інформація про навчальну групу.

Вихідні дані:
- Результат перевірки.
- Інформація про конфлікти.
- Статус збереження розкладу.

## 4. Взаємодія компонентів

Web Interface передає запити до Schedule Controller.

Schedule Controller звертається до Schedule Service для виконання бізнес-операцій.

Schedule Service взаємодіє з Validation Service, Conflict Checker та Schedule Repository.

Після виконання операції результат повертається через Schedule Controller до Web Interface.

## 5. Висновок

Визначені інтерфейси забезпечують взаємодію основних компонентів системи, розділення відповідальності та можливість незалежного тестування.
