# Архітектура системи Class Schedule System

## 1. Загальний опис

Class Schedule System — система для формування, перевірки та перегляду розкладу занять. Архітектура системи побудована на основі багаторівневого підходу (Layered Architecture).

## 2. Структура архітектури

Система складається з чотирьох основних рівнів.

### 2.1 Presentation Layer

Рівень представлення відповідає за взаємодію користувача із системою.

Основний компонент:
- Web Interface — вебінтерфейс для роботи з розкладом.

### 2.2 Application Layer

Рівень застосунку відповідає за обробку запитів користувачів.

Основні компоненти:
- Schedule Controller — обробка операцій із розкладом.
- User Controller — обробка операцій із користувачами.

### 2.3 Business Logic Layer

Рівень бізнес-логіки реалізує основні правила роботи системи.

Основні компоненти:
- Schedule Service — керування розкладом.
- Validation Service — перевірка коректності даних.
- Conflict Checker — виявлення конфліктів у розкладі.
- User Service — робота з користувачами.

### 2.4 Data Access Layer

Рівень доступу до даних відповідає за збереження та отримання інформації.

Основні компоненти:
- Schedule Repository — робота з даними розкладу.
- User Repository — робота з даними користувачів.
- Class Schedule Database — база даних системи.

## 3. Взаємодія компонентів

Користувач надсилає запит через Web Interface. Запит передається відповідному контролеру Application Layer.

Контролер звертається до сервісів Business Logic Layer, де виконуються перевірки та обробка бізнес-правил.

Для отримання або збереження інформації сервіси використовують репозиторії Data Access Layer.

Після завершення операції результат повертається користувачу через контролер та вебінтерфейс.

## 4. Основні принципи архітектури

- Розділення відповідальності між рівнями.
- Мінімізація залежностей між компонентами.
- Повторне використання компонентів.
- Можливість незалежного тестування окремих рівнів.
- Централізована перевірка коректності розкладу.

## 5. Висновок

Обрана багаторівнева архітектура забезпечує структурованість системи Class Schedule System, спрощує її підтримку, тестування та подальше розширення.
