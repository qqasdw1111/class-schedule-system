# ADR-001: Використання багаторівневої архітектури

## Статус
Прийнято

## Контекст
Система Class Schedule System повинна забезпечувати перегляд, створення, редагування та перевірку розкладу занять. Для розділення відповідальності між компонентами необхідно визначити архітектурний підхід.

## Розглянуті варіанти
- Монолітна архітектура без розділення рівнів.
- Багаторівнева архітектура.
- Мікросервісна архітектура.

## Рішення
Обрано багаторівневу архітектуру (Layered Architecture).

Система поділяється на такі рівні:
1. Presentation Layer — інтерфейс користувача.
2. Application Layer — контролери та обробка запитів.
3. Business Logic Layer — бізнес-логіка та перевірка розкладу.
4. Data Access Layer — робота з базою даних.

## Наслідки
- Спрощується підтримка системи.
- Компоненти мають чітко визначені обов'язки.
- Полегшується тестування окремих рівнів.
- Зміни в одному рівні менше впливають на інші рівні.
