# ADR-002: Використання реляційної бази даних

## Статус
Прийнято

## Контекст
Система Class Schedule System повинна зберігати інформацію про студентів, викладачів, навчальні групи, дисципліни, аудиторії та розклад занять. Необхідно обрати спосіб організації та зберігання цих даних.

## Розглянуті варіанти
- Реляційна база даних.
- Документно-орієнтована база даних (NoSQL).
- Зберігання даних у файлах.

## Рішення
Обрано використання реляційної бази даних.

Дані будуть організовані у взаємопов'язані таблиці з використанням первинних та зовнішніх ключів.

Основні сутності:
1. Student — студенти.
2. Teacher — викладачі.
3. StudyGroup — навчальні групи.
4. Subject — дисципліни.
5. Classroom — аудиторії.
6. Schedule — розклад.
7. Lesson — заняття.

## Наслідки
- Забезпечується цілісність даних.
- Спрощується пошук та фільтрація інформації.
- Підтримуються зв'язки між сутностями.
- Можна використовувати SQL-запити.
- Потрібно підтримувати структуру таблиць та зв'язків.
